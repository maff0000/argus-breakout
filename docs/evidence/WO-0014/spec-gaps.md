# WO-0014 — Spec gaps and residuals

1. **The trading-gap discriminator cannot tell a same-company exit from a reassignment when the store holds no history across the gap.** For all 22 excluded symbols no bar exists on or before the final membership end; for 10 of them (CA, CMA, FL, HBI, JWN, LEG, PDCO, SEE, SRCL, TGNA) the first stored bar after is the first Polygon day (2024-10-21), so their Polygon-era bars are excluded although at least some (HBI, JWN, LEG, FL, TGNA, CMA, PDCO, SRCL) are very probably the same company still trading. The loss is 8,480 bars of non-members; no feature reads them today. A symbol that exits the index before the Polygon window and later rejoins would hit this. Options for the Architect: accept as a stated limit; or bootstrap former members' history from yfinance (an ingestion decision, not a materialisation one).
2. **Special dividends on the same ex-date look lost from Polygon.** PGR 2025-01-10: Polygon 0.10 vs yfinance 4.60; 2026-01-02: 0.10 vs 13.60; FCX every quarter 0.075 vs 0.15; WRB, CME, DVN, FANG, COP similar. Polygon takes precedence, so `adj_close` for those ex-dates carries only the smaller amount: PGR's 2026-01-02 adjustment is ~0.10 instead of ~13.60 (about 5% of price). The mechanism is **not established**: the Polygon provider emits one row per record and `upsert` keys on (symbol, date, source), which would keep one of several same-date records, but this has not been checked against the API response. Needs a one-symbol look at the raw Polygon payload before anything is built; if confirmed it is a defect in WO-0004's ingestion (summing or keeping a `dividend_type`), and it affects every return-type feature on the affected dates.
3. **Naming debt:** `n_days_quarantined_skipped`, the CLI text "quarantined days not published", and the `read_ingest_verdicts` vocabulary now cover every non-`ok` status. Left unrenamed to stay inside scope.
4. **Test gap (Auditor 1):** the ex-date handling inside the dividend comparison helper is not pinned by `test_dividend_disagreement_normalises_basis`; the applied factor is (`test_split_on_ex_date_is_divided_out`).
5. **`test_latest_verdict_wins` uses `time.sleep(0.01)`** to order verdicts: a minor flake risk (Implementer observation).
6. **`source_disagreement` grew 2,832 → 3,136** because the recovered tails overlap two sources; it is the same WO-0007 channel and not a new defect, but it is now the dominant warning kind (3,136 of 3,220).
